# 솔로 대화 신뢰성 개선

작성: 2026-11-11

## 탐색 결과와 우선순위

1. **이번 구현 — 대화 요청과 세션 수명 정합성.** 연속 전송하면 앞선 답을 버리는 구조이고, 친구 통화로 이동할 때 요청이 무효화되지 않는다. 같은 캐릭터 재입장은 화면 기록만 비우고 서버 세션을 재사용한다. 외부 서비스 없이 회귀 검증할 수 있고 핵심 대화 경험에 직접 영향을 준다.
2. **다음 — 기분 기록 저장과 조회.** 현재 저장 버튼의 콜백은 비어 있다. 로컬 저장·삭제·날짜별 조회 및 민감 정보 보관 정책을 함께 설계해야 한다.
3. **다음 — 통화 진입의 실제 연결.** 친구 통화가 현재 랜덤 매칭 PoC로 연결되고 음소거·신고 콜백은 비어 있다. 친구 초대와 매칭을 분리하고 시그널링 연결 전 완료된 통화 기능으로 취급하지 않는다.
4. **후속 — 기기 접근성과 렌더 품질.** 카메라 거부·미지원 기기에서 텍스트 대화를 허용하는 진입 구조, iOS Unity 준비 콜백, 실기기 성능 측정이 남아 있다.

## 범위와 구현 계획

- 한 대화에서 응답 요청은 하나만 진행한다. 동기 잠금으로 빠른 연속 입력도 막는다.
- 기다리는 동안 전송 버튼과 예시 문장을 비활성화하고 대기 문구를 표시한다. 다음 메시지 초안 작성은 허용하며 보내지 않은 초안은 유지한다.
- 최종 어댑터 실패는 안내하고 다시 입력할 수 있게 한다. 자동 재전송은 서버 중복 처리 가능성 때문에 하지 않는다. 기존 원격→스크립트 폴백 정책은 유지한다.
- 뒤로가기·친구 통화·언마운트 시 이전 요청의 성공/실패/완료 처리가 화면 상태에 영향을 주지 않는다. 네트워크 요청 자체의 취소와 서버 기록 삭제는 이 범위에 포함하지 않는다.
- 솔로 화면 이탈 시 화면 기록과 응답 상태를 비운다. 다시 입장하면 같은 캐릭터라도 앱이 생성하는 원격 어댑터와 세션을 새로 만든다. 주입한 테스트 어댑터의 수명은 호출자가 관리한다.

## 완료 조건

- 대기 중 전송·예시 문장을 눌러도 어댑터는 한 번만 호출되고 초안은 유지된다.
- 응답 후 다음 요청에는 앞선 사용자 메시지와 답이 순서대로 전달된다.
- 실패 안내 후 다시 메시지를 보낼 수 있다.
- 화면 이탈 후 늦은 성공/실패가 새 대화를 오염시키지 않는다.
- 같은 캐릭터로 재입장해도 원격 세션은 새로 생성된다.
- 모바일 테스트, 타입 검사, lint 통과.

## 후속 항목 구현 (2026-11-11)

### 기분 기록

- `MoodStore`가 저장·조회·개별 삭제·전체 삭제를 제공한다. 쓰기를 직렬화해 동시에 저장/삭제해도 기록을 덮어쓰지 않는다. 저장은 500자 이내, 기기 현지 날짜(YYYY-MM-DD) 기준이며 과거 날짜 버튼/날짜 입력으로 조회한다.
- Android는 앱 전용 `noBackupFilesDir`의 AtomicFile, iOS는 Application Support/MurmurPrivate의 원자적 파일 쓰기와 파일 보호를 쓴다. iOS 디렉터리는 백업 제외 설정한다. 기록은 네트워크/AI 요청에 포함하지 않는다.
- 사용자가 삭제하거나 앱을 삭제할 때까지 보관한다. 삭제는 확인 후 실행한다. 저장 성공 후에만 입력을 비운다. 저장소가 없거나 기록이 손상되면 오류를 표시하고 덮어쓰지 않는다. 전체 삭제로 손상된 저장소를 초기화할 수 있다.

### 친구 초대와 랜덤 매칭

- 솔로의 친구 통화 버튼은 `CallLobby`로 이동한다. 친구 초대 코드 생성/코드 입장과 랜덤 매칭 요청은 별도 버튼이다. 기존 무한 connecting PoC와 비어 있는 음소거/신고 콜백 연결은 내비게이터에서 제거했다.
- `packages/shared-types`에 시그널링 wire 타입을 공유한다. 앱은 서비스 코드를 import하지 않는다.
- 개발용 HTTP 게이트웨이: POST `/connect`, `/send`, `/poll`, `/close`. 연결별 임의 토큰, 커서 기반 이벤트 확인, 60초 비활성 정리, 2인 초대방, 요청 크기·형식 검증을 지원한다. 앱이 1초마다 이벤트를 가져오며 연결 실패를 표시한다. 화면 종료 시 연결을 정리한다.
- 방 생성 → 상대 입장 → 퇴장, SDP/ICE 중계, 현재 세션 상대 신고 및 차단을 기존 signaling 코어에 연결했다. 차단은 같은 연결 식별자에 대한 서버 메모리 상태이며 계정 기반 영구 차단은 아니다.
- **상대 입장은 음성 통화 연결이 아니다.** 화면에 음성·표정 전송 미지원 상태를 명시하며 음소거 버튼은 제공하지 않는다. WebRTC 미디어 엔진/STUN·TURN/SFU는 이 구현에 포함하지 않는다.
- 인증 서비스가 없으므로 HTTP 클라이언트가 `adult`를 보내도 서버는 `unverified`로 처리한다. 따라서 랜덤 매칭은 인증 필요 안내를 표시한다. 사용자 입력만으로 성인 권한을 부여하지 않는다. 기존 코어의 검증된 성인 간 매칭 테스트는 유지한다.
- 서버 실행: `pnpm --filter @murmur/signaling dev` (기본 127.0.0.1:8788). 앱 개발 주소는 `SIGNALING_URL`. 실기기 연결 시 명시적으로 서버 HOST와 앱 LAN 주소를 설정해야 한다. 배포용 인증·TLS·영속 신고 저장은 별도 출시 작업이다.

### 텍스트 접근성과 네이티브 수명

- 온보딩 및 트래킹 미지원 기기 안내에서 텍스트 모드로 진입한다. 이 모드에서는 카메라와 Unity 렌더러를 시작하지 않는다. Android 카메라 하드웨어 요구를 선택으로 변경했고 최소 OS/ABI는 유지한다.
- 개발 빌드의 연결 화면에 `내 표정 미리보기`를 별도로 둔다. 카메라 권한을 거부해도 이 화면에서 텍스트 대화로 전환할 수 있다. 미리보기는 통화로 표시하지 않는다.
- 비동기 카메라 권한/아바타 로드가 화면 종료 후 끝나면 트래커를 시작하지 않는다. 트래커 시작 자체가 늦게 끝나면 다시 중지한다.
- Unity iOS 플러그인이 준비 알림을 보내고 Swift 프록시가 대기 중인 LoadAvatar/SetTheme/SetMotion을 전달한다. 준비 전 프레임은 버리고 제어 메시지는 슬롯별 최신 값만 보관한다(최대 32개). 기존 뷰 attach/pause(false) 처리는 유지한다.

### 검증 및 남은 실환경 작업

- 모바일: 대화 신뢰성, 저장 직렬화·재열기·삭제·실패, 날짜 조회, 텍스트 진입, 친구방 UI, HTTP 클라이언트 종료, 늦은 트래커 시작 방지 회귀 테스트.
- signaling: 친구방 생성·입장·퇴장, 커서 확인, 만료, 요청 검증, 성인 권한 위조 거부, HTTP 라우팅 테스트. 소켓 바인딩 없이 실제 서버 request handler에 요청을 전달하는 방식으로 검증했다.
- 전체 TypeScript 타입·ESLint·모듈 경계 검사, Unity Editor/Android/iOS 조건부 C# 컴파일 검사, Swift 구문 파싱, Objective-C/Objective-C++ 구문 검사.
- **실기기 성능 수치는 아직 측정하지 않았다.** 이 환경에서 ADB 소켓 바인딩이 거부됐고 Android Gradle은 사용자 캐시 잠금 파일 쓰기 권한 때문에 빌드하지 못했다. 새 네이티브 저장 모듈과 Unity iOS 플러그인은 앱/Unity 재빌드 후 실제 기기에서 재시작 영속성·표정 표시·fps/지연을 확인해야 한다. 기존 APK/UnityFramework에는 이번 변경이 포함되어 있지 않다.
