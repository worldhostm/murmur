# 스펙: ai-character

상태: 뼈대 구현됨 (2026-11-06). 실제 공급자 어댑터는 미구현.

## 목적

사용자 음성과 표정 신호를 받아 AI 캐릭터의 말·음성·입 모양(face-protocol 프레임)을 스트리밍으로 만든다. 솔로 모드의 안전 원칙(위기 대응, 의존 방지, 사람과의 연결 권유)을 코드 수준에서 보장한다.

## 범위

- 어댑터 인터페이스: STT, LLM, TTS. 테스트용 가짜 구현.
- 표정 신호 추출: face-protocol 프레임 → `{ smile, frown, gazeAway, fatigue }` 수치. 영상은 받지 않는다.
- viseme → 블렌드셰이프 매핑과 fps 보간. 결과는 `validateFrame`을 통과한다.
- 캐릭터 4종 페르소나(`characters/<id>.md` 원문, `src/persona` 요약)와 시스템 프롬프트 생성.
- 위기 키워드 감지 → LLM 우회 → 서비스 말투의 109 안내.
- 장시간(90분)·심야(1~5시) 휴식 권유 판단.
- `ConversationPipeline`: 대화 기록(최근 40개), 응답 생성, 프레임 타임스탬프 연속성.

## 범위 밖

- 실제 STT/LLM/TTS 공급자 연동 (어댑터 구현은 별도 스펙)
- 대화 요약·장기 기억 저장소 (`summarize()`는 자리표시자)
- 음성 스트림 전송(WebRTC/SFU), GPU 렌더
- 표정 신호 휴리스틱의 실데이터 보정 (0단계 PoC)

## 완료 조건

- [x] smile 픽스처에서 smile > 0.7, frown ≈ 0
- [x] 30fps 프레임 수 = ceil(길이 / 33.3ms), 전 프레임 validateFrame 통과, aa 에서 jawOpen 최대
- [x] 위기 문장 감지(한/영), 일반 문장 미감지, 위기 경로가 LLM 호출 0회이며 응답에 '109' 포함
- [x] 휴식 권유: 90분 이상 또는 1~5시
- [x] 시스템 프롬프트에 'AI 캐릭터' 명시, 솔로 원칙 포함, 미성년·미인증이면 로맨스 금지
- [x] 가짜 어댑터로 end-to-end: 텍스트, 프레임 ≥ 1, 기록 증가, 기록 상한
- [x] 페르소나 4종 모두 공통 금지 목록 포함

## 열린 질문

- 위기 감지를 키워드에서 분류기로 바꿀 때 오탐·미탐 기준을 어떻게 둘지
- 표정 신호를 프롬프트 문장으로 넣을지, 구조화된 입력으로 넣을지 (LLM 공급자에 따라 다름)
- 캐릭터별 voiceId 와 TTS 공급자 매핑
