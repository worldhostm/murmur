# 디자인 개선안: 폰트·가독성·화면 구조

작성: 2026-11-11
상태: 1차 구현 반영. 아래 제안 원문과 마지막 적용 현황을 함께 확인한다.
기준: `docs/DESIGN_SYSTEM.md`, 현재 모바일 컴포넌트·테마·화면 코드.

## 1. 목표와 조사 범위

Murmur의 라벤더·크림·보라 색상과 조용한 분위기는 유지한다. 대화 문장을 편하게 읽고, 키보드가 열린 상태에서도 입력과 응답 확인을 이어갈 수 있게 한다. 캐릭터, 대화, 기분 기록의 시각적 우선순위를 분명히 한다.

이번 진단은 저장소 코드와 에셋 목록을 기준으로 했다. 기기 스크린샷이나 실기기 렌더링을 확인한 결과는 아니다. 아래 수치는 구현을 위한 제안값이며, 폰트 번들 후 iOS/Android 실제 렌더링으로 확정한다. 외부 폰트 제품 비교보다 이미 정한 Noto 계열의 적용 완성도를 우선한다.

## 3. 폰트 적용 계획

### 3.1 패밀리 역할

- 본문·입력·버튼·상태·날짜: **Noto Sans KR**.
- 온보딩 감성 문장과 캐릭터 소개 이름: **Noto Serif KR**.
- 캐릭터 목록 이름은 Serif 정체성을 유지하되 소개 화면보다 작게 쓴다.
- 오류·권한 안내·일반 페이지 제목은 Sans로 통일한다. 감성용 Display 스타일을 일반 안내 제목에 사용하지 않는다.
- 본문 굵기 400, 메타 정보 500, 버튼·섹션 제목 600, 페이지 제목 700의 기존 역할을 유지한다. 한 문단 전체를 굵게 처리하지 않는다.

### 3.2 번들 및 검증

1. 기존 폰트 README가 지정한 Sans 400/500/600/700, Serif 600의 정적 파일 5개를 번들한다. 가변 폰트 도입은 별도 검증 전까지 보류한다.
2. 배포본과 일치하는 라이선스 및 출처를 함께 보관하고, 파일별 용량과 앱 용량 증가분을 기록한다.
3. Android의 파일명, iOS의 실제 패밀리/스타일 이름과 앱 등록을 확인한다. 파일명만 보고 정상 적용으로 판단하지 않는다.
4. 테스트 문자열로 한국어·영어·숫자·문장부호·이모지 혼합을 확인한다. 예: `오늘은 조금 괜찮았어요. 11월 11일, 23:40 / Leon Hart 🙂`.
5. 굵기 400/500/600/700이 각각 구분되는지, TextInput과 AppText가 같은 본문 메트릭을 쓰는지 확인한다. 합성 굵기나 의도치 않은 시스템 폰트 대체가 없는지 본다.
6. 번들 실패 시 개발 환경에서 탐지할 수 있도록 에셋 존재 검사와 매핑 테스트를 둔다. 시스템 폰트 대체는 의도된 fallback으로 정의하고 누락을 정상 적용으로 보고하지 않는다.

## 4. 타이포그래피 제안

수치는 React Native 논리 단위 기준이다. 기존 타입 토큰을 정리하고 신규 역할은 토큰 제안으로 추가한다. 변경 시 `tokens.json` → 생성 코드 → 디자인 시스템 표를 함께 맞춘다.

| 역할 | 현재 | 제안 | 적용 기준 |
| --- | --- | --- | --- |
| 감성 큰 문장 `display-lg` | Serif 40/48, 600 | 기본 유지. 좁거나 세로 공간이 부족하면 32/42의 compact 역할 | 온보딩만. 고정 줄바꿈으로 화면 폭을 가정하지 않음 |
| 소개 이름 `display-md` | Serif 28/36, 600 | 유지 | 캐릭터 상세/소개용 |
| 목록 이름 `character-name` | 별도 역할 없음 | Serif 24/32, 600 | 캐릭터 선택 목록. 이름이 길면 줄바꿈 허용 |
| 화면 제목 `title` | Sans 20/28, 700 | 유지 | 한 화면의 목적 |
| 섹션 제목 `heading` | Sans 17/24, 600 | 유지 | 기록/초대 등 하위 그룹 |
| 대화·입력 `body` | Sans 15/24, 400 | Sans 16/26, 400 | 한국어 문단과 입력 중 문장을 같은 크기로 맞춤 |
| 설명 `body-sm` | Sans 13/20, 400 | Sans 14/22, 400 | 프라이버시·연결 제한·오류·도움말 포함 |
| 버튼 `label` | Sans 15/20, 600 | Sans 15/22, 600 | 영문과 큰 글자에서 줄바꿈 가능 |
| 메타 `caption` | Sans 12/16, 500 | 유지 | 날짜·짧은 배지·보조 메타만. 필수 설명 금지 |

- 본문 자간은 기본값을 유지한다. 한글 폭을 줄이기 위해 음수 자간을 일괄 적용하지 않는다.
- 줄바꿈은 글꼴과 언어에 맞춰 확인한다. 긴 URL·공백 없는 문장도 화면 밖으로 나가지 않아야 한다.
- 문장 내용은 줄 수 제한으로 잘라내지 않는다. 캐릭터 소개의 요약만 제한할 수 있으며, 전체 내용을 볼 수 있는 동선을 함께 둔다.
- Dynamic Type/Android 글자 배율을 따른다. 공간 부족은 배치 변경으로 해결한다. 일반 제목·버튼·채팅에 통화 오버레이의 1.3배 제한을 확장하지 않는다.

## 5. 공통 화면·컨트롤 레이아웃

### 5.1 화면 골격

- 헤더: 뒤로가기와 화면 제목을 한 영역으로 묶는다. 현재처럼 뒤로가기 다음에 큰 섹션 간격이 다시 붙어 제목이 과도하게 내려가지 않게 한다.
- 콘텐츠: 세로 스크롤 하나가 본문을 책임지도록 한다. 스크롤 내부에 또 다른 세로 스크롤을 중첩하지 않는다.
- 하단 행동: 지속적으로 필요한 입력·확인 버튼은 본문과 분리한다. 시스템 하단 안전 영역과 키보드 인셋을 반영한다.
- 기본 좌우 여백은 기존 16, 섹션 간격 24를 유지한다. 제목과 설명은 8, 입력 라벨과 필드는 8, 연관된 행동은 12로 묶는다.
- 600 이상의 화면 폭에서는 본문 최대 폭 560을 제안한다. 가운데 정렬된 콘텐츠 영역 안에서 글자와 컨트롤은 좌측 정렬한다.
- 좁은 화면/큰 글자에서는 가로 버튼을 세로로 바꾼다. 긴 라벨을 축소해 억지로 한 줄에 넣지 않는다.

### 5.2 공통 입력 필드

`LabeledInput` 역할을 정의해 채팅을 제외한 기록·초대 입력에 재사용한다.

- 상시 표시 라벨 → 입력 필드 → 도움말 또는 오류 순서.
- 최소 높이 52, 좌우 패딩 12, 세로 패딩 12, `radius-sm`, `surface-200` 배경.
- 기본 경계는 `border-strong`, 포커스는 `brand`, 오류는 `danger`와 오류 문구를 함께 사용한다. 조합별 대비는 실제 색상 테스트로 확인한다.
- placeholder는 예시이며 라벨을 대체하지 않는다. 예: 라벨 `초대 코드`, placeholder `ABC234`.
- 상태는 기본/포커스/입력 완료/비활성/오류로 나누고, 비활성 이유가 필요한 경우 아래 설명을 둔다.
- 기분 입력은 여러 줄과 현재 글자 수를 지원한다. 저장 실패 시 내용 유지 여부를 명시한다.

### 5.3 버튼과 선택 상태

- 한 화면에 채움형 주 버튼은 하나만 둔다. 채팅은 전송, 기록 화면은 저장, 초대 화면은 현재 선택한 흐름의 실행이 주 행동이다.
- 모든 행동을 52 높이의 pill 버튼으로 나열하지 않는다. 보조 이동은 텍스트 버튼, 날짜 선택은 선택 칩, 삭제는 기록의 보조 메뉴로 구분한다. 각각 터치 영역은 최소 48을 유지한다.
- 버튼은 최소 높이만 지정하고 여러 줄 라벨에 맞춰 늘어난다. 세로 패딩과 중앙 정렬을 함께 정의한다.
- 선택된 날짜/캐릭터는 배경뿐 아니라 체크 또는 선택 문구와 접근성 상태로 표시한다.
- 삭제·차단은 `danger` 계열의 별도 destructive 역할을 제안한다. 기본 초대/저장과 같은 시각적 무게로 나열하지 않는다.

## 6. 솔로 대화 화면

### 6.1 제안 구조

```text
안전 영역
[뒤로] 캐릭터 이름 · AI 캐릭터     [기록]
[캐릭터 미리보기 — 펼침/접기]
─────────────────────────────────────
대화 목록                              ← 이 영역만 스크롤
사용자/캐릭터 메시지
[새 메시지 보기]                        ← 과거 대화를 읽고 있을 때
─────────────────────────────────────
응답 대기 또는 오류 안내                ← 있을 때만
[메시지를 입력하세요             ] [전송] ← 키보드 위에 유지
하단 안전 영역 / 키보드
```

### 6.2 대화 공간 확보

- 고정 아바타의 기본 높이를 192로 제안하고, 실제 사용할 수 있는 세로 공간의 30%를 상한으로 둔다. 카메라/렌더 영역을 강제로 늘려 입력창을 밀어내지 않는다.
- 키보드가 열리면 큰 아바타를 접고 48 크기의 초상과 이름을 헤더에 남긴다. 닫히면 사용자가 선택한 펼침 상태로 복귀한다.
- 글자 배율 1.5 이상 또는 작은 가로 화면에서는 축소 상태를 기본으로 제안한다. 사용자가 펼쳐도 입력창은 항상 접근 가능해야 한다.
- 텍스트 모드는 빈 아바타 자리를 두지 않고 헤더와 대화 목록으로 바로 시작한다.
- AI 표시는 대화 헤더에 항상 남긴다. 반복 말풍선의 배지를 줄이는 변경은 헤더가 스크롤·키보드 상태와 무관하게 보이는 구조를 먼저 구현한 뒤 검토한다. 현행 디자인 시스템 §7의 변경 사항으로 함께 관리한다.

### 6.3 입력·스크롤

- 메시지 입력은 1~5줄 범위에서 늘어나고 이후에는 입력 내부가 스크롤된다. 한국어 조합 입력 중 Enter 처리와 줄바꿈/전송의 구분을 확인한다.
- 대화 목록은 메시지 수에 맞는 가상화 목록을 사용한다. 헤더/입력창은 목록 바깥에 둔다.
- 하단 근처에 있거나 사용자가 메시지를 보낸 경우에만 새 메시지로 이동한다. 현재의 내용 크기 변경마다 `scrollToEnd` 하는 방식은 과거 대화 읽기 위치를 유지하도록 변경한다.
- 화면 뒤집기, 글자 확대, 기록 시트 닫기만으로 읽고 있던 위치를 잃지 않는다.
- 기분 기록 전체 목록과 친구 연결 버튼을 대화 목록 끝에 쌓지 않는다. 기록은 헤더의 진입점, 친구 연결은 대화 메뉴의 명확한 항목으로 제공한다.

| 화면 | 개선안 | 상태별 기준 |
| --- | --- | --- |
| 온보딩 | 큰 문장·짧은 설명·시작 영역의 세 그룹. 기본 시작은 주 버튼, 텍스트 시작은 보조 버튼 | 작은 화면이나 큰 글자는 본문 스크롤 허용. 시작 버튼과 글자가 겹치지 않음 |
| 캐릭터 선택 | 이름 아래 AI 배지를 배치해 폭 경쟁 완화. 이름→한 줄 역할→짧은 세계관 순으로 정리. 목록 이미지 크기는 공통 토큰화 | 좁은 화면/큰 글자는 세로 카드. 하단 시작 버튼에 선택한 이름 표시, 선택 상태는 체크와 접근성 값 제공 |
| 오늘 기분 | 대화에서 열면 기록 작성에 집중하는 시트 또는 화면. 짧은 로컬 보관 안내, 여러 줄 입력, 저장 상태 | 실패하면 초안을 유지하고 필드 근처에 안내. 키보드 위 저장 버튼 유지 |
| 기록 조회 | 오늘/최근 날짜/날짜 선택으로 범위를 좁히고 날짜별 목록 표시. 모든 날짜를 pill 버튼으로 펼치지 않음 | 빈 기록·조회 실패·저장소 손상을 구분. 전체 삭제는 관리 영역, 개별 삭제는 각 기록 메뉴 |
| 친구 연결 | `친구 초대`와 `코드로 입장`을 별도 선택 영역으로 구성. 랜덤 매칭은 자격 안내가 있는 하위 영역 | 초대 생성 후 코드를 크게 표시하고 복사/공유 제공. 코드가 없을 때 입력 폼을 상시 강요하지 않음 |
| 연결 상태 | 초대 대기·상대 입장·연결 오류의 상태 블록을 일관되게 표시 | 상대 입장은 음성 연결로 표현하지 않음. 재시도 가능 여부와 다음 행동을 함께 표시 |
| 미지원 기기 | 제목 `텍스트로 대화할 수 있어요` 중심으로 대안 우선. 기기 사유는 보조 설명 | 실패 화면처럼 과장하지 않음. 지원하지 않는 기능과 사용할 수 있는 기능을 명확히 구분 |

복사/공유, 기록 전용 화면, 메시지 위치 보존은 UI 배치와 함께 필요한 동작까지 구현해야 완료로 본다. 이번 문서 작성에서 해당 기능이 추가된 것은 아니다.

## 9. 구현 순서와 완료 조건

| 단계 | 구현 단위 | 완료 조건 |
| --- | --- | --- |
| 1 · P0 | 폰트 번들·굵기 매핑·타입 스케일 | iOS/Android에서 실제 Noto 사용 확인, 한국어/영어 혼합 문자열과 4종 굵기 검증, 용량 증가 기록 |
| 2 · P0 | 공통 헤더·입력 컴포넌트·키보드 입력창 | 키보드가 열린 채로 메시지 입력/전송/오류 확인 가능. 라벨·오류 잘림 없음 |
| 3 · P1 | 대화 목록/아바타 배치/스크롤 유지 | 과거 대화 읽는 중 자동 이동하지 않음. 큰 글자·가로 화면에서도 입력창 접근 가능 |
| 4 · P1 | 기록 화면·날짜 필터·선택 카드·초대 화면 | 기록 100개와 긴 이름에서도 반복 버튼으로 화면을 채우지 않음. 초대/입장/오류 동선 구별 가능 |
| 5 · P2 | 넓은 화면·시각적 정리 | 콘텐츠 최대 폭, 정렬, 두 테마, 모션 감소 및 접근성 점검 완료 |

### 검증 매트릭스

- 플랫폼: iOS와 Android 각각 실제 화면 확인. 스냅샷만으로 폰트 적용을 확인했다고 판단하지 않는다.
- 폭: 320/360/390/430/768 논리 단위, 가로 방향과 작은 세로 높이 포함.
- 글자 배율: 1.0/1.3/1.5/2.0. 운영체제에서 제공하는 더 큰 접근성 크기도 탐색 확인.
- 언어: 한국어/영어, 긴 캐릭터 이름, 긴 버튼 라벨, 공백 없는 메시지.
- 키보드: 닫힘/열림, 한글 조합 입력, 여러 줄 입력, 화면 회전, 하단 안전 영역.
- 데이터: 빈 대화/긴 대화, 빈 기록/100개 기록, 초대 전/대기/입장/오류.
- 테마/접근성: light/dark, 스크린리더 탐색 순서, 선택 상태, 터치 영역 48 이상, 상태 안내, 동작 줄이기.
- 자동 검사: 새 토큰 생성 일치, light/dark 컴포넌트 스냅샷, 본문 4.5:1 및 해당 컨트롤 3:1 대비, 입력·선택·스크롤 상태 회귀 테스트.

### 수용 기준

- 필수 문장, 입력 내용, 주요 버튼이 잘리거나 서로 겹치지 않는다.
- 대화를 읽거나 입력하는 데 불필요한 화면 스크롤을 요구하지 않는다.
- 기능의 실제 상태와 디자인상 표현이 일치한다. 상대 입장을 통화 연결로, 폰트 fallback을 지정 폰트 적용으로 보고하지 않는다.
- 신규 토큰, 컴포넌트, 화면 변경은 DESIGN_SYSTEM.md와 본 문서의 완료 항목에 함께 반영한다.


## 10. 1차 적용 현황

사용자 요청에 따라 바로 적용 가능한 타이포그래피·레이아웃을 구현했다.

- 적용: 본문/설명/버튼 타입 스케일, 작은 온보딩/캐릭터 이름 토큰, 공통 라벨 입력, 헤더·하단 영역·최대 폭, 여러 줄 채팅 입력과 키보드 대응 구조.
- 적용: 메시지 목록 가상화, 이전 대화 읽기 중 자동 이동 방지/새 메시지 이동, 키보드·큰 글자에서 아바타 축소, 기록 전용 화면과 작성/조회 탭, 최근 7개 날짜/20개씩 기록 표시.
- 적용: 캐릭터 이름과 AI 배지 세로 배치, 선택 표시, 하단 시작 버튼, 초대/코드 입장 분리, 초대 코드 시스템 공유와 길게 눌러 복사.
- 보류: Noto 파일 번들·네이티브 글꼴 등록, 실제 iOS/Android 시각 검수, 전체 접근성 매트릭스, 디자인 추가 고도화. 앱이 지정 폰트를 실제 사용한다고 검증한 것은 아니다.
- 기능 회귀 테스트와 두 테마 스냅샷, 토큰/대비 검사를 우선 검증한다. 이후 작업은 작은 단위로 나누어 진행한다.

## 11. 폰트 준비 1차 작업 (2026-11-12)

- 현재 Noto 바이너리·라이선스 파일이 없고 다운로드 DNS 요청이 실패했다. 따라서 폰트 번들 완료로 처리하지 않는다.
- `assets/fonts/manifest.json`으로 활성 상태와 5개 정적 얼굴의 파일명·굵기·PostScript 이름을 관리한다. 비활성 상태에서는 iOS System/Android sans-serif로 명시적으로 대체한다. Serif의 시각적 정체성은 실제 Noto 번들 후 복원한다.
- `fonts:check`/`fonts:test`와 CI 검사를 추가했다. 활성화 시 파일 메타데이터·Android 복사본·iOS 등록 목록·OFL 파일을 검사한다. `--require-bundled`는 비활성 상태도 실패로 반환한다.
- 다음 단위: 실제 폰트/라이선스 확보 → 네이티브 등록 → 재빌드 및 실기기 확인. 현재 검사 도구의 성공과 실제 폰트 렌더링 성공을 구분한다.
