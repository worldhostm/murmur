# ADR-0002: 표정 데이터는 face-protocol 규격 하나로만 주고받는다 (contract-first)

날짜: 2026-11-06 · 상태: 채택

## 맥락

앱(TypeScript), Unity 렌더러(C#), iOS 트래커(Swift/ARKit), Android 트래커(Kotlin/MediaPipe), 통화 서버, AI 캐릭터 서비스가 모두 표정 데이터를 다룬다. 언어마다 타입을 손으로 맞추면 세션이 바뀌고 시간이 지나며 어긋난다. 또한 "원본 영상은 기기 밖으로 보내지 않는다"는 원칙을 코드 구조로 보장해야 한다.

## 결정

- `packages/face-protocol/schema/face-frame.schema.json` 을 유일한 원본으로 두고, TS·C#·Swift·Kotlin 타입과 상수를 생성한다. 생성물은 저장소에 커밋하되 직접 수정하지 않고, 테스트로 최신 여부를 강제한다.
- 모듈 간 표정 데이터 교환은 `FaceFrame` 과 v1 바이너리(144 B)만 쓴다. 영상·픽셀 필드는 규격에 넣지 않는다.
- 버전은 헤더에 담고, 현재 버전과 바로 이전 버전까지 디코딩한다.
- 블렌드셰이프 순서는 ARKit 52개 순서를 그대로 따른다. MediaPipe 도 같은 이름을 쓰므로 변환 비용이 없다.

## 대안

- **Protobuf / FlatBuffers**: 다국어 생성이 강점이지만 고정 144 B 레이아웃에는 과하고, Unity·RN 양쪽에 런타임 의존성이 생긴다. 필드가 늘어 가변 길이가 필요해지면 재검토한다.
- **JSON 전송**: 디버깅은 쉽지만 30 fps 에서 크기가 10배 이상이고 파싱 비용이 크다. JSON 은 픽스처·디버깅 용도로만 둔다.
- **언어별 수동 타입**: 가장 빠르지만 어긋남을 막을 수 없어 기각.

## 결과

- 트래커·렌더러·서버는 어댑터에서 `FaceFrame` 으로 바꾸기만 하면 된다.
- 규격 변경은 스키마 수정 → 버전 증가 → `pnpm generate` → 이전 버전 디코더 유지의 절차를 따른다.
- 실시간 표정 픽스처를 재생해 카메라 없이 CI 에서 렌더 스냅샷 테스트를 돌릴 수 있는 기반이 된다.
